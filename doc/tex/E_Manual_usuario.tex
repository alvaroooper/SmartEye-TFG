\apendice{Documentación de usuario}

\section{Introducción}

Este apéndice recoge la documentación orientada al usuario final de la aplicación desarrollada en este Trabajo de Fin de Grado. A diferencia de la documentación técnica de programación, esta sección no describe la instalación interna del sistema, la configuración de Docker, la base de datos ni las dependencias del proyecto.

Desde el punto de vista del usuario, la aplicación se utiliza como una plataforma web. Por tanto, una vez desplegada por el personal técnico o por el administrador del sistema, el usuario solo necesita acceder a la dirección proporcionada mediante un navegador web.

El objetivo de este apéndice es explicar los requisitos básicos de acceso y dejar preparada la sección posterior del manual de usuario, donde se describirá el uso funcional de la aplicación: registro, inicio de sesión, ejecución de pipelines, consulta de resultados, gestión de compras y funciones de administración.

\section{Requisitos de usuarios}

Para utilizar la aplicación no es necesario instalar Python, MariaDB, Docker, Docker Compose ni ninguna dependencia interna del proyecto. Todos esos elementos forman parte del despliegue técnico y se documentan en el apéndice de documentación técnica de programación.

El usuario únicamente necesita disponer de:

\begin{itemize}
	\item \textbf{Navegador web actualizado}: necesario para acceder a la interfaz de la aplicación.
	\item \textbf{Conexión a Internet}: o acceso a la red en la que esté desplegada la plataforma.
	\item \textbf{Dirección de acceso}: URL proporcionada por el administrador o responsable técnico.
\end{itemize}

En un entorno local de demostración, la aplicación puede estar disponible en:

\begin{bloqueCodigo}[title={url de acceso}]
	http://localhost:5000
\end{bloqueCodigo}

En caso de acceder desde otro equipo de la misma red, deberá utilizarse la dirección IP o URL proporcionada por el administrador del sistema.

En un despliegue real, el acceso se realizaría mediante la URL pública o privada configurada para la plataforma.

\section{Instalación}

Desde el punto de vista del usuario final, no es necesario instalar la aplicación ni preparar ningún componente técnico en su equipo.

La aplicación se utiliza directamente desde un navegador web, accediendo a la dirección proporcionada por el administrador o responsable del sistema. La instalación, configuración y despliegue de la plataforma corresponden al personal técnico y se describen en la documentación técnica de programación.

Por tanto, el usuario solo necesita disponer de un navegador web actualizado, conexión a Internet o acceso a la red donde esté desplegada la aplicación, y una cuenta válida para iniciar sesión.

La aplicación se ejecuta escuchando en \texttt{0.0.0.0:5000} para permitir conexiones desde fuera del contenedor. Sin embargo, cuando se accede desde el propio equipo anfitrión, la URL habitual de acceso es \texttt{http://localhost:5000}.

\subsection{Panel principal del usuario}

Una vez autenticado, el usuario accede al panel principal. Esta pantalla permite seleccionar un pipeline de inteligencia artificial, cargar una configuración opcional y subir la imagen que se desea analizar. La Figura~\ref{fig:manual_dashboard_usuario_panel} muestra el panel de ejecución principal.

\begin{figure}[H]
	\centering
	\includegraphics[width=\linewidth,height=0.78\textheight,keepaspectratio]{interfaces/interfaz_dashboard_usuario_panel.png}
	\caption[Panel principal del usuario]{Panel principal para lanzar una secuencia de inteligencia artificial.}
	\label{fig:manual_dashboard_usuario_panel}
\end{figure}

El flujo habitual de uso es el siguiente:

\begin{enumerate}
	\item Seleccionar el pipeline que se desea ejecutar.
	\item Cargar la configuración predeterminada o introducir una configuración personalizada en formato JSON.
	\item Seleccionar una imagen desde el equipo.
	\item Pulsar el botón \textit{Ejecutar Red Neuronal}.
	\item Esperar a que el servidor procese la imagen y genere los resultados.
\end{enumerate}

La configuración personalizada es opcional. Si el usuario no necesita modificar parámetros internos del modelo, puede utilizar la configuración predeterminada.

\subsubsection{Configuración avanzada de ejecución}

El usuario puede sustituir la configuración predeterminada por una configuración avanzada en formato JSON. Esta opción permite ajustar parámetros de inferencia como la confianza mínima, el tamaño de entrada o la complejidad del modelo.

La aplicación valida que el texto introducido sea un JSON correcto, pero no comprueba en profundidad los valores internos. Por tanto, se presupone que el usuario conoce el efecto de los cambios realizados.

\paragraph{MediaPipe manos.}
Permite detectar manos y sus puntos clave.

\begin{bloqueCodigo}[title={MediaPipe manos}]
	{
		"max_num_hands": 2,
		"min_detection_confidence": 0.5
	}
\end{bloqueCodigo}

\begin{itemize}
	\item \texttt{max\_num\_hands}: máximo de manos a detectar. Entero $\geq 1$.
	\item \texttt{min\_detection\_confidence}: confianza mínima de detección. Rango habitual: 0.0--1.0. Valores altos son más estrictos.
\end{itemize}

\paragraph{MediaPipe pose.}
Permite estimar la postura corporal mediante puntos clave.

\begin{bloqueCodigo}[title={MediaPipe pose}]
	{
		"model_complexity": 1,
		"min_detection_confidence": 0.5
	}
\end{bloqueCodigo}

\begin{itemize}
	\item \texttt{model\_complexity}: complejidad del modelo. Valores habituales: 0, 1 o 2. A mayor valor, mayor precisión y coste.
	\item \texttt{min\_detection\_confidence}: confianza mínima de detección. Rango habitual: 0.0--1.0.
\end{itemize}

\paragraph{YOLO detección.}
Permite detectar objetos en la imagen.

\begin{bloqueCodigo}[title={YOLO detección}]
	{
		"conf": 0.25,
		"iou": 0.45,
		"imgsz": 1280
	}
\end{bloqueCodigo}

\begin{itemize}
	\item \texttt{conf}: confianza mínima para aceptar detecciones. Rango habitual: 0.0--1.0.
	\item \texttt{iou}: umbral de solapamiento para filtrar cajas duplicadas. Rango habitual: 0.0--1.0.
	\item \texttt{imgsz}: tamaño de entrada del modelo. Entero positivo. Valores mayores pueden mejorar el detalle, pero aumentan el tiempo de ejecución.
\end{itemize}

\paragraph{YOLO recortes de personas.}
Permite detectar personas y generar recortes independientes.

\begin{bloqueCodigo}[title={YOLO recortes}]
	{
		"conf": 0.30,
		"iou": 0.6,
		"imgsz": 1280,
		"scale_factor": 1.0
	}
\end{bloqueCodigo}

\begin{itemize}
	\item \texttt{conf}: confianza mínima para aceptar una persona detectada. Rango habitual: 0.0--1.0.
	\item \texttt{iou}: umbral de solapamiento para filtrar cajas duplicadas. Rango habitual: 0.0--1.0.
	\item \texttt{imgsz}: tamaño de entrada del modelo. Entero positivo.
	\item \texttt{scale\_factor}: ampliación del recorte. Real $> 0$. El valor 1.0 mantiene el tamaño original.
\end{itemize}

En pipelines con varias etapas, la configuración se organiza con claves como \texttt{etapa\_1}, \texttt{etapa\_2} o sucesivas, aplicándose cada bloque a su fase correspondiente.

\subsection{Cierre de sesión}

Para salir de la aplicación, el usuario debe utilizar el botón \textit{Salir} o \textit{Salir del sistema}, disponible en la barra superior o en el menú lateral según la pantalla. Al cerrar sesión, se abandona la zona privada y será necesario volver a introducir las credenciales para acceder de nuevo.
