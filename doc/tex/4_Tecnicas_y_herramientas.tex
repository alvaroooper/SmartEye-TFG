\capitulo{4}{Técnicas y herramientas}

En este capítulo se describen las tecnologías y herramientas seleccionadas para el desarrollo del proyecto. La elección de este \textit{stack} tecnológico responde a un análisis de eficiencia, seguridad y compatibilidad técnica, priorizando soluciones de código abierto y ampliamente respaldadas por la comunidad profesional.

\section{Visión por Computador e Inteligencia Artificial}

La capacidad de procesamiento visual es el núcleo de este proyecto. Se han seleccionado herramientas que permiten un equilibrio entre precisión y rendimiento en tiempo real:

\begin{itemize}
	\item \textbf{MediaPipe:} Framework de Google especializado en la detección de puntos clave corporales. 
	\textit{Justificación:} A diferencia de modelos basados puramente en aprendizaje profundo que requieren GPUs de alto rendimiento, MediaPipe está optimizado para ejecutarse de forma eficiente en CPU mediante el uso de grafos de procesamiento. Esto garantiza que la aplicación sea accesible en una mayor variedad de dispositivos sin sacrificar la latencia \cite{lugaresi2019mediapipe, google_mediapipe_docs}.
	
	\item \textbf{YOLO (You Only Look Once) v8:} Modelo de detección de objetos por regresión. 
	\textit{Justificación:} Se ha optado por la versión v8 de Ultralytics por ser el estándar actual en velocidad. Mientras que otros modelos como Faster R-CNN requieren dos etapas de procesamiento, YOLO realiza la detección en una sola pasada, lo que resulta crítico para sistemas que requieren una respuesta inmediata ante la cámara \cite{ultralytics_yolov8}.
	
	\item \textbf{OpenCV (cv2):} Librería de visión artificial por excelencia.
	\textit{Justificación:} Se utiliza como "pegamento" técnico para la manipulación de imágenes. Su ventaja competitiva reside en su madurez y en la capacidad de manejar flujos de vídeo de forma nativa, permitiendo tareas de preprocesamiento (como el redimensionado o filtrado de ruido) que son costosas de implementar desde cero en Python \cite{opencv_docs}.
\end{itemize}

\section{Desarrollo Backend y Lógica de Negocio}

Para la construcción de la API y la orquestación de datos, se ha utilizado el ecosistema de Python, seleccionado por su sintaxis clara y su liderazgo en el sector de la IA:

\begin{itemize}
	\item \textbf{Flask:} Microframework web.
	\textit{Justificación:} Frente a frameworks "todo incluido" como Django, Flask ofrece una arquitectura minimalista. Esto evita la sobrecarga de componentes innecesarios y permite un control total sobre las rutas y la integración de los modelos de IA, facilitando un despliegue más ágil y ligero \cite{flask_docs}.
	
	\item \textbf{Flask-SQLAlchemy:} Capa de abstracción de base de datos (ORM).
	\textit{Justificación:} Su uso es fundamental para la seguridad y el mantenimiento. Al utilizar un ORM, se evita la escritura de consultas SQL manuales, lo que mitiga el riesgo de ataques de inyección SQL y permite interactuar con los datos mediante objetos de Python, facilitando la legibilidad del código \cite{sqlalchemy_docs}.
	
	\item \textbf{Flask-JWT-Extended:} Gestión de autenticación mediante JSON Web Tokens.
	\textit{Justificación:} Se ha elegido para implementar una arquitectura \textit{stateless} (sin estado). Esto permite que el servidor no tenga que almacenar sesiones en memoria, mejorando la escalabilidad y proporcionando un mecanismo robusto para proteger los \textit{endpoints} privados del sistema \cite{jwt_docs}.
	
	\item \textbf{Werkzeug y Python-dotenv:} Herramientas de utilidad y configuración.
	\textit{Justificación:} Werkzeug garantiza la seguridad de las credenciales mediante el \textit{hashing} de contraseñas, asegurando que no se almacenen en texto plano. Por otro lado, \texttt{python-dotenv} permite gestionar variables de entorno, manteniendo las claves privadas y credenciales de acceso fuera del código fuente \cite{dotenv_docs}.
\end{itemize}

\section{Gestión de Datos}

\begin{itemize}
	\item \textbf{MariaDB:} Sistema de gestión de bases de datos relacionales.
	\textit{Justificación:} Se ha seleccionado MariaDB sobre MySQL por su excelente rendimiento en la gestión de hilos y su naturaleza totalmente \textit{open-source}. Es la solución ideal para garantizar la integridad referencial de los datos de usuarios y registros históricos con una alta disponibilidad \cite{mariadb_docs}.
\end{itemize}

\section{Diseño y Diagramación}

Para la fase de planificación visual y modelado arquitectónico, se han empleado las siguientes herramientas:

\begin{itemize}
	\item \textbf{dbdiagram.io:} Herramienta de diseño de bases de datos basada en código.
	\textit{Justificación:} Permite definir el esquema Entidad-Relación de forma rápida mediante lenguaje descriptivo (DSL). Su uso ha sido clave para iterar el modelo de datos de MariaDB antes de su implementación física, asegurando que todas las relaciones fuesen correctas.
	
	\item \textbf{Draw.io:} Aplicación de diagramación profesional.
	\textit{Justificación:} Se ha utilizado para crear los diagramas de arquitectura del sistema, flujos de datos y lógica de los algoritmos de visión. Su versatilidad permite documentar visualmente el proyecto de forma estandarizada.
\end{itemize}

\section{Documentación y redacción técnica}

\begin{itemize}
	\item \textbf{LaTeX:} Sistema de preparación de documentos de alta calidad.
	\textit{Justificación:} Se ha utilizado para la redacción de la memoria del TFG por su capacidad para estructurar documentos técnicos de forma rigurosa y profesional. \section{Entorno de Desarrollo e Infraestructura}

Esta sección comprende el sistema operativo y las aplicaciones que han permitido la escritura, depuración y control del software:

\begin{itemize}
	\item \textbf{Linux (Debian):} Sistema operativo base.
	\textit{Justificación:} Elegido por su estabilidad crítica y su gestión avanzada de permisos. Debian proporciona un entorno de servidor estandarizado donde las dependencias de Python y las librerías de IA se ejecutan de forma previsible y segura \cite{debian_docs}.
	
	\item \textbf{Visual Studio Code:} Entorno de desarrollo integrado (IDE).
	\textit{Justificación:} Su potencia reside en su ecosistema de extensiones y su terminal integrada. Facilita la depuración de código en tiempo real y la integración directa con el control de versiones, optimizando el tiempo de desarrollo \cite{vscode_docs}.
	
	\item \textbf{DBeaver:} Cliente de base de datos universal.
	\textit{Justificación:} A diferencia de herramientas básicas, DBeaver permite administrar MariaDB de forma visual, ejecutar consultas de prueba y monitorizar el estado de las tablas sin necesidad de usar la línea de comandos, lo que reduce errores humanos en la manipulación de datos.
	
	\item \textbf{GitHub:} Plataforma de control de versiones distribuido.
	\textit{Justificación:} Es fundamental para garantizar la trazabilidad del código. Permite mantener un histórico de cambios, trabajar en diferentes ramas de desarrollo y asegurar que el trabajo esté respaldado en la nube \cite{github_docs}.
\end{itemize}

\section{Gestión y Comunicación del Proyecto}

\begin{itemize}
	\item \textbf{Jira:} Gestión del ciclo de vida del software.

Permite la planificación de \textit{Sprints}, la priorización de tareas en el \textit{Backlog} y el seguimiento detallado del progreso, asegurando que se cumplen los hitos del TFG en el tiempo previsto \cite{jira_docs}.
	
	\item \textbf{Microsoft Teams:} Centro de colaboración.
	\textit{Justificación:} Ha servido como canal de comunicación persistente para reuniones de seguimiento y compartición de documentos técnicos, manteniendo un histórico de las decisiones tomadas durante el desarrollo \cite{teams_docs}.
\end{itemize}
