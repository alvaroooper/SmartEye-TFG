\apendice{Especificación de Requisitos}

\section{Introducción}
Este apéndice recoge los requisitos y casos de uso del \textbf{Producto Mínimo Viable (MVP)} del sistema. El MVP se centra en: \textit{autenticación de usuarios (Básico, Pro y Administrador), selección de IA, subida de imagen, procesamiento y descarga del resultado}, con despliegue funcional para demostración. Se excluyen funcionalidades no imprescindibles (por ejemplo, historial de compras, pipelines de IAs, auditorías avanzadas).

\section{Objetivos generales}
\begin{itemize}
	\item Permitir el acceso de usuarios autenticados (Básico, Pro y Administrador) a una plataforma web.
	\item Ofrecer un flujo completo: \textbf{seleccionar Pipeline de IAs y modos} \textrightarrow\ \textbf{subir imagen} \textrightarrow\ \textbf{procesar} \textrightarrow\ \textbf{visualizar resultado} \textrightarrow\ \textbf{descargar}.
	\item Aplicar control de acceso en servidor según el plan (Básico/Pro) y rol (Administrador).
	\item Garantizar que las imágenes y resultados sean \textbf{temporales}.
	\item Disponer de un despliegue reproducible para que la aplicación esté operativa (demo).
\end{itemize}

\section{Catálogo de requisitos}

\subsection{Requisitos funcionales (MVP)}

\textbf{RF-MVP-1 Gestión de cuentas de usuario}\\
La aplicación debe permitir registrar, iniciar sesión y cerrar sesión para acceder al sistema.
\begin{itemize}
	\item RF-MVP-1.1 Registro de usuario.
	\item RF-MVP-1.2 Inicio de sesión.
	\item RF-MVP-1.3 Cierre de sesión.
	\item RF-MVP-1.4 Modificar datos de cuenta.
\end{itemize}

\textbf{RF-MVP-2 Roles y planes (Básico, Pro, Administrador)}\\
La aplicación debe distinguir los tres tipos de usuario y aplicar permisos en servidor.
\begin{itemize}
	\item RF-MVP-2.1 Rol Administrador con acceso a panel de gestión.
	\item RF-MVP-2.2 Plan Básico: acceso únicamente a IAs activas para ese usuario.
	\item RF-MVP-2.3 Plan Pro: acceso a todas las IAs disponibles.
	\item RF-MVP-2.4 Visualización del plan actual (Básico/Pro) y estado.
\end{itemize}

\textbf{RF-MVP-3 Catálogo de IAs y modos (según permisos)}\\
La aplicación debe mostrar y permitir seleccionar únicamente pipelines con IAs y modos permitidos.
\begin{itemize}
	\item RF-MVP-3.1 Catálogo general de pipelines de IAs disponibles en el sistema.
	\item RF-MVP-3.2 Modos asociados a cada IA.
	\item RF-MVP-3.3 Filtrado del catálogo por plan/rol en la interfaz.
\end{itemize}

\textbf{RF-MVP-4 Subida puntual de imagen}\\
La aplicación debe permitir subir una imagen para procesarla sin persistencia.
\begin{itemize}
	\item RF-MVP-4.1 Subir imagen desde el panel de análisis.
	\item RF-MVP-4.2 Validación básica (tipo y tamaño máximo).
	\item RF-MVP-4.3 Uso temporal y eliminación automática tras el procesamiento.
\end{itemize}

\textbf{RF-MVP-5 Procesamiento con IA, visualización y descarga}\\
La aplicación debe ejecutar el análisis con la IA seleccionada y permitir descargar el resultado.
\begin{itemize}
	\item RF-MVP-5.1 Selección de pipeline (IAs y modos).
	\item RF-MVP-5.2 Ejecución del procesamiento.
	\item RF-MVP-5.3 Mostrar imagen procesada como resultado principal.
	\item RF-MVP-5.4 Mostrar JSON del análisis como resultado secundario.
	\item RF-MVP-5.5 Descargar la imagen procesada.
\end{itemize}

\textbf{RF-MVP-6 Restricciones y manejo de errores}\\
La aplicación debe impedir acciones no permitidas y mostrar mensajes claros.
\begin{itemize}
	\item RF-MVP-6.1 Impedir ejecutar IAs no permitidas.
	\item RF-MVP-6.2 Impedir procesar si no hay sesión iniciada.
	\item RF-MVP-6.3 Error de imagen inválida: informar y no procesar.
	\item RF-MVP-6.4 Error interno: informar sin detalles técnicos.
\end{itemize}

\textbf{RF-MVP-7 Interfaz web del flujo principal}\\
La aplicación debe disponer de una interfaz web centrada en el flujo del MVP.
\begin{itemize}
	\item RF-MVP-7.1 Pantallas: registro, login, ajustes, panel de análisis, resultado y descarga.
	\item RF-MVP-7.2 Selectores dinámicos: modos cambian según IA.
\end{itemize}

\textbf{RF-MVP-8 API mínima (soporte de demo e integración)}\\
La aplicación debe exponer endpoints básicos para comprobación y ejecución.
\begin{itemize}
	\item RF-MVP-8.1 Endpoint de salud del sistema.
	\item RF-MVP-8.2 Endpoint de catálogo permitido según usuario.
	\item RF-MVP-8.3 Endpoint de ejecución de análisis (imagen, IA, modo).
\end{itemize}

\textbf{RF-MVP-9 Administración mínima}\\
El administrador debe poder ver usuarios y su plan para soporte básico.
\begin{itemize}
	\item RF-MVP-9.1 Listado de usuarios con plan/rol.
	\item RF-MVP-9.2 Ver detalle de usuario (plan/estado).
\end{itemize}

\subsection{Requisitos no funcionales (MVP)}

\textbf{RNF-MVP-1 Usabilidad}\\
Interfaz clara, centrada en el flujo principal, con mensajes comprensibles.

\textbf{RNF-MVP-2 Rendimiento}\\
Procesamiento en tiempos razonables y limitación de tamaño de imagen.

\textbf{RNF-MVP-3 Seguridad}\\
Autenticación obligatoria, aislamiento entre usuarios y validación de ficheros.

\textbf{RNF-MVP-4 Portabilidad y despliegue}\\
Ejecución reproducible (local o servidor) con configuración centralizada y dependencias documentadas.
